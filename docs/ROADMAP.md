# Roadmap

Este roadmap reflete objetivos e lacunas identificados nas conversas. Não representa promessa de prazo.

## Fase 0 — Preservar o que existe

- [ ] Recuperar o código-fonte original do site publicado.
- [ ] Registrar stack, dependências e comandos para executar localmente.
- [ ] Identificar banco de dados, modelo de dados e integrações.
- [ ] Capturar telas e mapear rotas/fluxos existentes.
- [ ] Comparar cada item de FUNCIONALIDADES.md com o comportamento real.
- [ ] Criar instruções seguras de configuração e deploy.

## Fase 1 — Estabilizar a aplicação web

- [ ] Validar lançamentos individuais e compartilhados.
- [ ] Validar cálculos de rateio e saldo 50/50.
- [ ] Validar parcelas, pendências e repasses.
- [ ] Validar Carteira e Painel de Alunos.
- [ ] Validar experiência responsiva e estados de erro/vazio.
- [ ] Criar testes automatizados para cálculos financeiros.

## Fase 2 — Acesso compartilhado

- [ ] Definir fluxo de convite/liberação da segunda pessoa.
- [ ] Implementar autenticação e autorização adequadas.
- [ ] Garantir isolamento entre espaços/contas.
- [ ] Definir sincronização e resolução de conflitos.
- [ ] Testar uso simultâneo em dois dispositivos.

## Fase 3 — Aplicativo Android

- [ ] Escolher estratégia técnica para Android.
- [ ] Definir experiência instalável e distribuição do APK.
- [ ] Validar em dois celulares Samsung.
- [ ] Implementar sincronização confiável.
- [ ] Implementar notificações push configuráveis.
- [ ] Documentar permissões e privacidade.

## Fase 4 — Preparação SaaS

- [ ] Definir multi-tenancy e modelo de contas.
- [ ] Definir papéis, convites e permissões.
- [ ] Definir planos e cobrança.
- [ ] Criar onboarding e gestão de assinatura.
- [ ] Definir suporte, auditoria, backup e observabilidade.

## Prioridade imediata

A prioridade técnica é obter o código-fonte real do site e fazer um inventário. Sem isso, não é seguro afirmar qual stack existe nem prometer que a documentação já representa integralmente a implementação.
